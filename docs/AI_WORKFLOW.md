# Model routing for this game

The user prioritizes implementation completeness and verification quality. Efficiency means choosing an appropriate model and effort for each bounded task, not reducing the agreed release scope or accepting partial mechanics.

| Work | Route | Escalation |
| --- | --- | --- |
| Exact files/counts/symbols | rg/tools, then Luna low | Broaden context or move to Sol when synthesis is required |
| Data extraction and ordinary implementation | Sol medium | High for conflicting requirements or repeated failed tests |
| Combat mechanics and transactional progression | Terra or Sol high | Stronger model/context review when design or behavior remains unresolved |
| UI integration | Terra or Sol with effort matching complexity | Independent visual/source review before acceptance |
| Architecture and independent correctness review | Role-appropriate independent model | Astra for high-impact cross-system decisions |

Model names and reasoning levels are separate controls. Native fixed-role files can override caller settings: runtime traces must confirm requested routes. Use a model-flexible native role when a specific user-requested model is necessary. Never fake a model by naming a task after it.

Keep existing Codex authentication and Claude configuration separate. No paid API fallback or new provider is implied. The global default effort was changed from xhigh to medium with a backup; task-specific high/xhigh remains available where correctness needs it.

Do not substitute copied counts, invented sample progress, screenshots or headless tests for actual gameplay, device evidence or shipped artifacts. A cheaper incomplete result is not an acceptable optimization.
