# Godot 1.0 expansion implementation

Authority: `docs/gdd/FULL_DESIGN.md`, release1.0 targets and per-content behavior, plus the user's original-game visual direction. User authorizes autonomous completion, parallel agents, model diversity and existing public deployment. Scope cannot be reduced merely to save inference cost.

## Binding constraints

- Preserve the existing quick300s and legacy expedition600s/boss510s rules, saved records and application/package identity. Add a distinct `campaign`900s/boss810s mode for release content.
- Release has24 spells,36 fusions,96 artifacts,6 zones/bosses/classes and24 research nodes; also24 normal variants across12families,18 elites, the specified12 events and F01-F04 resonance choices. Every advertised item needs actual behavior and evidence, not a renamed duplicate or placeholder.
- Keep the simulation separate from rendering and persistence. No new runtime dependencies, account/backend/payment or fabricated progress.
- Same-frame death > deadline > boss kill; phase/lifecycle pauses freeze timers and clear captured movement.
- Campaign:6 learned spell slots, maxLv5,3 fusions, materialLv3, materials retained. No invented four-artifact inventory cap.
- Research has24 one-time purchases, costs10/18/28/40 by GDD ranges,6 equipped points, purchase-only prerequisites, free hub configuration and no combat-time purchase/equip.
- Reward formula and first-seen/first-clear flags are atomic, validated and idempotent per run. Quick/legacy/practice/abandon grant no campaign currency. Existing records.json remains compatible.
- Preserve original black/olive/ink visual grammar. Reference screenshots and generated runtime assets remain different roles; never pretend a screenshot is a finished terrain tile or animation.
- Model and effort are separate choices: Luna for bounded retrieval, Terra/Sol for implementation with high effort for combat/save correctness, independent architecture/review when needed. Escalate on unresolved errors instead of accepting weaker work.

## Tasks and ownership

1. Release catalog and stable mapping: structured GDD tables to `data/release_content.json`, reusable extraction/validation tool; keep legacy content.json unchanged. Own catalog/tool/tests only.
2. Campaign profile: `scripts/progression.gd` and isolated progression tests. Own profile schema, research transactions, reward/discovery/best records; no edits to legacy records.gd.
3. Release simulation: `scripts/release_simulation.gd`, minimal documented legacy extension seams only where needed, release combat/effect helpers and dedicated tests. Own combat/state/zone/boss/class/event/resonance behavior.
4. Native hub and presentation: `scripts/hud.gd`, `game.gd`, required view helpers/assets and UI tests. Connect campaign factories/profile without implementing duplicate combat rules. Six map/class selection, research, codex, event/resonance choices and truthful results.
5. Root integration: schema/interface ledger, targeted suites, independent task and final review, native/browser/emulator acceptance, PDF/source status update, APK/Web exports and public deployment.

## Integration interfaces

- `release_content.json` uses existing slug IDs for M01-M08/F01-F04/A001-A012 and stable new `m09`/`f05`/`a013` IDs. Every entry also carries its canonical GDD ID. Zones/classes/research/events use Z01/C01/R01/E01 IDs.
- `ReleaseSimulation` exposes the same `state/catalog/start/tick/choose_upgrade/choose_artifact/toggle_pause/orbit_position` API as Simulation; constructor/reset additionally accept `{zoneId,classId,research,runId}` options. Release-only phases add `event` and `resonance` with explicit choose/decline APIs.
- `Progression` exposes `data,last_error,load_profile,set_in_run,purchase_research,set_equipped,complete_run,for_zone`. Constructor accepts save path plus optional catalog; default profile path is separate from records.json. Methods return success/error without mutating persisted/in-memory accepted state on save failure.
- `complete_run(state)` accepts only valid terminal campaign results, uses `state.runId/zoneId/bossKind/completedEvents/bossSpawned/bossDefeated`, and returns `{ok,credited,reward,error}`. Duplicate completion is credited0; invalid state cannot mint rewards.

## Architecture review decisions

- Use inherited tick with ordered stage extraction, preserving legacy RNG/outcome order. Release damage must occur before the shared terminal stage.
- Base bolt lacks a level-zero guard: campaign must not grant hidden bolt to C02-C06.
- C06 viability repair: M15 now deals weak periodic glyph damage as well as slowing; retain the single starting spell. Update GDD source, catalog and tests together.
- Enemy definitions are the actual twelve families/two normal variants, not six generic families. Add18defined elites and their spawn windows/caps/retreat contract.
- ArtifactRules uses explicit modifiers/eligible/acquire/event/tick calls, deriveddepth1 recursion guard and agreed small combat primitives. Campaign exclusively owns legacy artifact effects to avoid double application.
